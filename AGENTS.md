# S3-Box Agent Instructions

## Architecture
- Clean architecture: `infrastructure → domain ← viewmodel ← view`
- Domain layer (`internal/domain`): Core business logic. Root entities: `connection_deck.ConnectionDeck` and `directory.Directory`
- ViewModel layer (`internal/ui/viewmodel`): Use case coordination, wraps domain entities, MVVM pattern
- View layer (`internal/ui/views`): Fyne GUI widgets and user interactions
- Infrastructure layer (`internal/infrastructure`): S3 access (AWS SDK v2), Fyne preferences, DTO mappings, notifications
- Entry point: `main.go` → `internal/ui/app` for dependency wiring
- Event-driven: Domain events flow through `event.Bus` interface (`github.com/thomas-marquis/it-happened`)

## Commands
- Build: `make` or `make build`
- Run: `make run`
- Test all: `make test`
- Test short (skip integration): `make test-short`
- Full check (lint + test): `make check`
- Generate mocks: `go generate ./...`
- Lint only: `./tools/lint.sh`

## Testing
- Integration tests use `testcontainers-go` with MinIO (`ministackorg/ministack`)
- Skip container tests in short mode: `if testing.Short() { t.Skip(...) }`
- Test utilities in `internal/tu` package
- Mocks generated by `gomock` in `mocks/` directories — never edit manually
- Mock declarations in `gen.go` at project root
- Use `gomock.NewController(t)` — no need for `defer ctrl.Finish()`
- Fyne tests: Initialize with `fyne_test.NewApp()` or `fyne_test.NewTempApp(t)`
- Image comparisons: `tu.AssertImageMatches(t, "images/<name>.png", canvas)`

## Development Environment
- Go 1.25+
- Python 3.13+ with `uv` for tooling (app doesn't need Python to run)
- Run scripts with `uv run` (e.g., `uv run ./tools/diff_images.py`)
- Docker Compose for local S3 testing: `docker-compose up` (MinIO on ports 9900/9901 and 9902/9903)
- Fyne GUI dependencies required for Linux builds

## Code Generation
- Mocks defined in `gen.go` — run `go generate ./...` to regenerate
- Mocks live under `mocks/` directories matching their package structure

## Conventions
- Follow layered architecture strictly — no circular dependencies
- Prefer explicit error handling
- Write short functions (≤100 lines)
- Use `// Given`, `// When`, `// Then` comments in tests
- Structure tests with `t.Run("should ...")` subtests
- Use `testify/assert` and `testify/require` for testing
- Don't comment code — use meaningful names instead
